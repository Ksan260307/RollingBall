# 設計メモ — 添付設計書をどう取り込んだか

添付の設計書（ADC）は、宇宙規模から極小スケールまでを完全決定論で扱うための枠組みでした。
その中核の考え方をこのゲームのコアロジックに使い、**専門用語は UI にもソースコードにも一切出さず**、
ふつうの言葉に置きかえています。この文書だけが、その対応表です。

## 対応表

| 設計書 | このゲームでの実装 | 使っている言葉 |
| --- | --- | --- |
| 完全決定論的状態遷移 | `src/core/simulation.ts` — 1/120 秒の固定きざみ、整数のみ、時計を見ない | 「同じ操作なら同じ結果」 |
| 64bit ビットパッキング SoA (§3.1) | `src/core/entities.ts` — 32bit×2 の並列配列に、進み具合・エネルギー・つかれ・段階・活動フラグを格納 | `low` / `high` スロット |
| 固定小数点演算・LUT (§7.1) | `src/core/fixed.ts` — 1/65536 単位の整数演算、`Math.sin` を使わない自前の角度表 | 「整数だけの計算」 |
| 空間ハッシュグリッド (§3.2) | `src/core/spatialGrid.ts` — 立方体に区切って近傍を引く。ハッシュ衝突は実セル照合で排除 | 「近くにあるものを探す」 |

## 物理の扱い

ボールは剛体として解いています。状態に回転速度を持ち、接地点でのすべりを摩擦が削り、
その反作用が回転を生みます。実装は `src/core/rolling.ts` と `src/core/simulation.ts` です。

| 現象 | 実装 |
| --- | --- |
| 転がり抵抗つきの坂の加速 | すべり速度をゼロに寄せる撃力を毎ステップ与える。結果として `g·sinθ/(1+k)` になる |
| 転がりと滑りの切り替え | 必要な撃力が `μ·N` を超えたら超えた分がすべりとして残る（クーロン摩擦） |
| 形状による慣性 | ボクセル配置から `I/(m·r²)` を算出。中身が詰まった球で約0.35、厚い殻で約0.47 |
| 着地 | 面法線方向の速度を打ち消し、強い着地のみ反発を残す |
| 壁 | 法線方向に反発、接線方向は法線撃力の `μ` 倍を上限にこすれ、回転が変化する |
| 空中 | 回転はほぼ保存。空気抵抗は速度の二乗に比例し、重いボールほど効きにくい |

質量は転がりの運動方程式からは（物理的に正しく）消えるため、重さは空気抵抗にのみ効きます。
ハンドルは「コース全体を傾ける」形にしてあり、重心を直接押していないので、
出足の速さがボールの形からそのまま決まります。

## 今回あえて採用しなかったもの

| 設計書 | 見送った理由 |
| --- | --- |
| WebGPU / WGSL・GPU 常駐演算 | スマホと PC の両方で確実に動くことを優先し、WebGL（Three.js）に統一。実体数が数百なので CPU で十分 |
| Hi-Z による Two-Pass Occlusion Culling | コースが一本道でオクルージョンが少なく、費用対効果が合わない |
| Hash-Grid Chunk SDF による動的地形化 | 「死骸が地形になる」要素が今回のゲーム性に無いため。空間グリッドの区画分けだけ流用 |
| 動的データ・リアライメント | 小物が動かないので、並び替えの必要が生じない |
| 完全な慣性テンソル（3x3）と重心オフセット | 主軸3方向の平均をスカラーとして使う近似にとどめた。ボールは幾何中心まわりに回るものとして扱っており、いびつな形の「振れ」は再現していない。形の効果は慣性の値として十分に出る |
| Time Dilation（Tick レートの動的増減） | ソロのタイムアタックでは、きざみ幅を変えないほうが記録の意味がはっきりする |
| WebRTC P2P 通信 | 今回はソロプレイのみという指定のため。土台は上表のとおり用意済み |

## 決定論をどう担保しているか

浮動小数点そのものではなく、**「結果が処理系ごとに変わりうる演算」**を排除しています。

- 位置・速度・角度はすべて 1/65536 単位の整数。四則演算のみで、丸め方は仕様で決まっています
- 三角関数は `Math.sin` を使いません。べき級数（四則演算のみ）で作った 4096 点の表と線形補間で求めます
- 平方根も `Math.sqrt` を使わず、整数のニュートン法で求めます。最初の当て推量に `Math.log2` のような
  近似関数を使うと処理系差が入りうるため、ビット位置を数える素朴なループにしています
- 乱数は `Math.random` を一切呼ばず、種と歩数から作ります
- 時計を読みません。経過時間は「何ステップ進んだか」で数えます

これらは `tests/fixed.test.ts` と `tests/simulation.test.ts` で確認しています。
とくに「走行中に `Math.random` と `Date.now` が一度も呼ばれないこと」は、直接テストしています。

## 将来 4 人プレイを入れるとき

必要になるのは通信部分だけで、ルール側の作りは変えなくて済むようにしてあります。

1. `World` はすでに 4 席分の配列を持っています（`MAX_PLAYERS`）。`players` を増やすだけで並走します
2. 送るのは `packControls()` が作る 1 ステップ 1 整数だけです。1 秒あたり 120 個、1 人 480 バイト程度
3. 相手の操作が遅れて届いたら、`capture()` の控えまで `rewind()` し、届いた操作を入れて流し直します
4. ときどき `World.checksum()` を突き合わせれば、ずれが起きていないか極小の通信量で確認できます
