# Steam版（デスクトップ）

Web版のビルドをそのまま包んで、**Steam でマルチプレイできる形**にするための殻です。
ゲーム本体には手を入れていません。`dist/` は Web版と同じものを読み込みます。

## なぜ殻が要るのか

Web版のマルチプレイは、**同じブラウザの別の窓としか**つながれません。
相手を見つけるには中継役のサーバがどこかに要り、静的ホスティングに置いたページには
それを用意する手段がないからです。

**Steam はそれを持っています。** ロビーも、誰が入っているかの管理も、
つながらないときの中継も、全部あります。だから Steam 版では通信の担当を Steam に渡します。

ゲーム側の通信の口は最初から差し替え可能な形（`Transport`）にしてあるので、
入れ替わるのはそこだけです。待合室もレースもルールも、どちらで動いているか知りません。

## 動かす

```bash
npm run desktop
```

`dist/` を相対パスでビルドし直してから Electron で開きます。

**Steam が動いていなくても起動します。** その場合はコンソールに一行出したうえで、
Web版と同じ「別の窓を探す」動作に戻ります。ロボットとのレースもそのままです。

## 配布用にまとめる

```bash
npm run desktop:pack
```

`desktop-build/win-unpacked/` に実行ファイル一式ができます。これを Steam の depot に上げます。

> **この環境では実行できませんでした。** electron-builder が Electron 本体を展開する途中で
> `default_app.asar` がロックされ、フォルダを変えても同じでした。ウイルス対策ソフトなどが
> 掴んでいる可能性が高く、設定の問題ではありません。通常のマシンでは通るはずです。

## Steam に出すまでに必要なこと

1. **App ID を取る**（Steamworks でアプリを登録する）
2. `desktop/steam_appid.txt` の中身を、その ID に書き換える
   - いまは **480**（Steam のテスト用アプリ "Spacewar"）が入っています。
     ロビーも P2P も本物と同じように動くので、開発中はこれで足ります
3. `package.json` の `build.appId` を自分のものに変える
4. depot に `desktop-build/win-unpacked/` の中身を上げ、
   起動オプションの実行ファイルを `RollingBallTimeAttack.exe` にする

### 気をつけるところ

- **`steamworks.js` は asar に入れてはいけません。** ネイティブのバイナリを持っているためです。
  `build.asarUnpack` で除外してあります
- **`steam_appid.txt` は実行ファイルと同じ場所に置きます。** `build.extraResources` で
  そこへ出るようにしてあります。Steam から起動された場合は不要ですが、
  直接起動して試すときに要ります

## 中身

| ファイル | 役割 |
| --- | --- |
| `main.cjs` | 窓を開き、Steam に触り、届いた通信をゲームに渡す |
| `preload.cjs` | ゲームと Steam のあいだの橋。**これ以外に何も渡していません** |
| `steam_appid.txt` | 開発中に Steam へ名乗る ID |

ゲームは `game://` という専用のしくみで自分自身を読み込みます。
ファイルから直接読むと**何をしてよいかの規則が付けられず**、Electron に警告されます。
同じファイルを自前の窓口から出すことで、規則を一緒に持たせています
（外部への通信も外部からの読み込みも全部禁止。このゲームはどちらも必要としません）。

## 通信量

送っているのは「何歩目に、誰が、どちらへ舵を切ったか」だけです。
1人あたり毎秒 120 回、1回 6 バイトほど。**位置も、玉の向きも、一切送っていません。**
全員の画面が同じ整数演算で同じレースを再現するので、それで足ります。
