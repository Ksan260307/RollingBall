# ころがしタイムアタック

高いところから低いところのゴールまで、ボールを転がしてかけぬける 3D タイムアタックゲームです。
スマートフォンでも PC でも遊べます。コースは 3 種類、それぞれ約 100 メートル。
コースから落ちるとそこで終了です。

ボールは自分で作れます。ブロックを削ったり足したりして形を変え、写真を貼って飾りつけできます。
作った形は転がり方にそのまま影響します。まん丸ならきびきび曲がり、いびつだとスピードが乗りにくくなります。

## あそびかた

| 操作 | スマートフォン | PC |
| --- | --- | --- |
| ボールを転がす | 画面をドラッグ | マウスをドラッグ / 矢印キー・WASD |
| カメラの近さ | 2 本指でピンチ | マウスホイール |
| 一時停止 | 右下のボタン | 右下のボタン / Esc |
| やりなおし | 一時停止 → もういちど | R キー |

ドラッグは「押した場所が中心」です。画面のどこを押してもかまいません。
左右がハンドル、上下が加速とブレーキになります。

## 公開（GitHub Actions）

`.github/workflows/ci.yml` が、プッシュとプルリクエストのたびに型チェック・テスト・ビルドを実行します。
`main` ブランチへのプッシュでは、続けて GitHub Pages へ公開します。

リポジトリ側の準備は 1 つだけです。

1. GitHub のリポジトリ設定 → **Pages** → **Source** を **GitHub Actions** にする

公開先はリポジトリ名のフォルダ配下になるため、ビルド時に `BASE_PATH` を渡しています。
ワークフローが自動で設定するので、手で書き換える必要はありません。

## 中身の作り

```
src/
  core/       ゲームのルール。画面のことは何も知りません
    fixed.ts        整数だけの計算（角度表・平方根など）
    random.ts       種から決まる乱数と照合用の合計値
    entities.ts     まわりの小物の状態を 64 ビットに詰めたもの
    spatialGrid.ts  近くにあるものを探す仕組み
    surroundings.ts 空気と地面のゆらぎ
    course.ts       コースの形と、ボールの位置の割り出し
    ballShape.ts    ブロックのかたまりから大きさ・重さ・丸さ・回しにくさを測る
    rolling.ts      転がりの計算（接地点のすべり、摩擦、スピン）
    input.ts        操作の記録（4 人分の席を用意）
    simulation.ts   1/120 秒きざみで進むゲーム本体
  game/       コースのデータ、1 回の挑戦の進行、保存
  render/     Three.js による描画
  ui/         画面と操作（表示する言葉は ui/text.ts にまとめてあります）
tests/        テスト一式
```

### 物理

ボールは点ではなく剛体として扱っています。回転そのものがシミュレーションの状態で、
地面はボールと接している一点だけで力を伝えます。すべっている分（接地点の速度）を
摩擦が削り取り、その削り取った分がそのままボールを回す力になります。

ここから、書き足さなくても次のことが起きます。

- 坂での加速は、すべる場合の `g·sinθ` ではなく、転がる場合の `g·sinθ /(1 + k)` になります
  （`k` は回しにくさ。中身の詰まった球なら 0.4 前後で、教科書どおり 5/7 に落ちます）
- ブロックの置き方で `k` が変わります。中心に寄せると出足が速く、外周に寄せると鈍くなります。
  エディタの「うごきだし」がこの値です
- 摩擦が足りない路面では、削り取りきれなかった分がそのまま「すべり」として残ります。
  氷では急な坂で直進していても滑り、ハンドルを切れば必ず滑ります。土けむりが出るのはそのときです
- 壁にぶつかると、跳ね返りと同時に壁をこするぶんの回転が加わります

計算はすべて整数のままです。テストでは、実測した加速度を理論値と突き合わせています
（10度の坂で 0.961 対 理論 0.970、`回転速度 × 半径` と速度の一致は 0.1% 以内）。

### 設計のかんどころ

ゲームの進行は **1/120 秒の固定きざみ**で、**整数だけ**を使って計算します。
時計も、種のない乱数も、一切参照しません。
そのため、同じコース・同じボール・同じ操作を与えれば、どの端末でも一字一句同じ結果になります。

この性質から、次のことが素直に実現できています。

- **リプレイが正確**。1 ステップにつき小さな整数 1 つを保存するだけで、走りを完全に再現できます
- **遠くの景色を捨てられる**。見えていない場所の小物はひとまとめの「メモ」に置きかえ、近づいたら同じ内容で復元します。捨てても結果は変わりません
- **将来の複数人対戦の下地**。やりとりするのは操作だけで済み、巻き戻しと再計算の仕組み（`capture` / `rewind`）も用意してあります

今回はソロプレイのみですが、席は 4 人分用意してあります（`MAX_PLAYERS`）。

### テスト

250 件のテストがあります。数値計算、乱数の再現性、小物の一生、コースの形、転がりの物理、リプレイ、
巻き戻し、メッシュの生成、画面の組み立て、操作の読み取り、保存まわりを確認しています。

物理のテストは、コードの出力をそのまま写したものではなく、坂の角度とボールの形から計算した
理論値と比べています。実装が現実の挙動からずれたら落ちます。

3 つのコースについては「素朴な自動運転で最後まで走りきれること」を毎回テストしています。
コース設計を変えて詰みが生まれた場合、テストが落ちて気づけます。

```bash
npm test
```

## 対応環境

WebGL が使える最近のブラウザで動きます（Chrome、Safari、Firefox、Edge）。
画面の狭い端末では表示を切り替え、ノッチやホームバーを避けて配置します。
`せってい` から、カメラの近さ・描画の細かさ・上下操作の反転を変更できます。
