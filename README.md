# ころがしタイムアタック

高いところから低いところのゴールまで、ボールを転がしてかけぬける 3D タイムアタックゲームです。
スマートフォンでも PC でも遊べます。コースは 3 種類、それぞれ約 100 メートル。
コースから落ちてもゲームオーバーにはならず、スタート地点に戻ってやりなおしです。
ただしタイムは止まらないので、落ちないほうが速くゴールできます。

ボールは自分で作れます。ブロックを削ったり足したりして形を変え、写真を貼って飾りつけできます。
**作った形は転がり方を大きく左右します。** でっぱりを1つ足すだけで角が地面を叩くようになり、
跳ねて、引っかかって、目に見えて進まなくなります。

### ボールをつくる画面

| やること | 操作 |
| --- | --- |
| 削る・足す・塗る | ブロックを **なぞる**（1個だけなら タップ） |
| 色をえらぶ | **カラーパレット**（31色・9色ずつ 3段＋別枠） |
| 色をつくる | パレット右端の **＋** で RGB の小窓。1つのボールに 12色まで |
| おもりの位置 | 下の丸いパッドを**ドラッグ**。重心をずらすと走りが変わります |
| かたちの下書き | まる／しかく／こつぶ／**ランダム** |
| ねらいの確認 | カーソルを重ねると、対象のブロックが**枠で光ります** |
| 回す | **なにもない ところ**をドラッグ |
| 拡大・縮小 | 2本指ピンチ / マウスホイール |
| やりなおし | 「ひとつ もどす」（30手前まで） |

枠の色が道具を表します。赤＝削る、黄＝足す、選んだ色＝塗る。
パレットは縦の列が同じ色あい、横の段が明るさ（あざやか／こい／うすい）です。
色をえらぶと道具は自動で「ぬる」に切りかわります。

**＋** を押すと R・G・B の小窓が開きます。作った色はパレットの後ろに並び、ボールと一緒に保存されます。
すでに作った色をもう一度押すと小窓が開いて**その色を直接いじれます**。
塗ったあとでも変えられ、その色で塗ったブロックがまとめて追従します。

| 操作 | スマートフォン | PC |
| --- | --- | --- |
| ボールを転がす | 画面をドラッグ | マウスをドラッグ / 矢印キー・WASD |
| カメラの近さ | 2 本指でピンチ | マウスホイール |

左右がハンドル、上下が加速とブレーキになります。

## コースを作る

エディタで作ったコースは `inGame` で**本編に出す・出さない**を切りかえられます。
消さずに寝かせておけるので、作りかけを抱えたままでもゲーム側は 3 コースのまま静かです。

コースの形は `src/game/courses.json` に置いてあり、**ゲームもエディタも同じファイルを読みます**。
開発用のコースエディタで編集して「本編に反映」を押せば、そのまま遊べます。

```bash
npm run courses
```

長さ・曲がり・下り・幅・傾き・床の種類・壁・とぎれを行ごとに並べていく形式で、
右側に 3D のプレビューが出ます。「ためし走行」を押すとゲーム本体と同じ自動運転で走らせ、
完走できるか・何秒かかるかをその場で確認できます。

エディタは **開発サーバーでのみ動き、配信物には一切含まれません**
（ビルドの入口はゲーム本体の `index.html` だけに固定してあります）。
くわしくは [tools/README.md](tools/README.md) を見てください。

## 中身の作り

```
src/
  core/       ゲームのルール。画面のことは何も知りません
    fixed.ts        整数だけの計算（角度表・平方根など）
    random.ts       種から決まる乱数と照合用の合計値
    entities.ts     まわりの小物の状態を 64 ビットに詰めたもの
    spatialGrid.ts  近くにあるものを探す仕組み
    surroundings.ts 空気と地面のゆらぎ
    course.ts       コースの形と、ボールの位置の割り出し
    ballShape.ts    ブロックのかたまりから大きさ・重さ・丸さ・回しにくさを測る
    rolling.ts      転がりの計算（接地点のすべり、摩擦、スピン）
    input.ts        操作の記録（4 人分の席を用意）
    simulation.ts   1/120 秒きざみで進むゲーム本体
  game/       コースのデータ、1 回の挑戦の進行、保存
    courses.json  コースそのもの。エディタが書きかえるのもこのファイル
  audio/      効果音（その場で合成。音声ファイルなし）
  render/     Three.js による描画
  ui/         画面と操作（表示する言葉は ui/text.ts にまとめてあります）
tests/        テスト一式
tools/        開発用ツール（配信物には含まれません）
  course-editor/  コースエディタ
```

### ランダムボール（本体24 × 組み立て3 × 仕上げ5 = 360通り）

「ランダム」は押すたびに**まったく別の形**が出ます。10 系統の作りかた
（コブの寄せ集め／ウニ／ドーナツ／石を積んだような塊／穴だらけ／細長いローラー／
房になったもの／原石のようにカットしたもの／殻／らせん階段）に、
色の塗りかた 6 通りと仕上げのコブ・かじり跡が乗るので、同じものはまず出ません。
実測で 30 個の種すべてが別の形になり、314〜1945 ブロックの幅がありました。

形が転がりを大きく左右するので、とがったものを引くとかなり手強くなります。
進めなくなれば 10 秒カウントで終わるので、遊べない形を引いても行き詰まりません。

### リプレイ

ゴールでも行き止まりでも、結果画面の **「リプレイ」** で走りをもう一度見られます。
再生中は画面の上に「リプレイ さいせい中」が出るので、自分の走行と間違えることはありません。

カメラは 2.6 秒ごとに勝手に動きまわり（後ろ・低め・高め・真横・前方・寄り）、
落下やゴール、強い着地では自動でスローになります。
「アングル」で自分で切りかえ、「はやさ」で ×0.35 / ×1 / ×2、
「さいしょから」で頭出し。ゴールを突き抜けるところまで見せたら 1.3 秒で頭に戻り、回りつづけます。

リプレイは**映像ではなく操作の記録**です。保存しているのは 1 ステップ 1 個の操作だけで、
それを新しいコースに流しこむと同じ走りが再現されます
（ルールが整数だけでできていて、時計も未指定の乱数も見ないため）。
数キロバイトで済み、どの速さで見ても結果は 1 ビットも変わりません。

### ゴールの演出

ゴールすると、ボールはそのまま線を突き破って向こう側へ飛んでいき、
1.7 秒で小さくなり、薄くなって消えます。カメラはゴール地点に残ったまま、飛んでいくボールだけを目で追います。
結果画面が出るころにはボールはもういません（ゴールして行ってしまったので、後ろで回りつづけたりしません）。

### ゴースト（自己ベストとの並走）

一度ゴールすると、その走りが**そのまま次の走行に並んで出てきます**。半透明のボールが
ベストのときと同じ線を走るので、どこで勝っていてどこで捨てているのかが目で見えます。

時計の下に **−0.42 / +0.31** と、ベストとの差が出ます。マイナスが速い、プラスが遅い。
`せってい` の「ベストの走りと ならんで走る」で切れます。記録を消すと走りも一緒に消えます。

保存しているのは**操作の記録だけ**（1コースあたり数十キロバイト）で、リプレイと同じしくみです。
ゴーストは自分の世界を持っていて、**本番の走りには一切さわれません**（ぶつかりませんし、
ゴーストがいてもいなくても走りは1ビットも変わりません — テストで確認しています）。

差の秒数は、ベストの走りが各メートルを通過した時刻を先に測っておき、目印の間を補間して出しています。
補間なしだと、動き出しの遅い区間で最大 1.8 秒ずれていました。いまは同じ走りに対して 0.05 秒以内です。

### 走っている感じ

- **軌跡** — 速度が上がるとボールの後ろに尾を引きます。色はそのコースの縁の色。
  遅いと出ません。`せってい` の「見た目を軽く」を入れると消えます
- **速さの光** — 速いほど画面のふちが明るくなります。まん中には何も出さないので、ボールの邪魔をしません
- **視野** — 速いほど画面が少しずつ広がります。気づかない程度の変化ですが、速さが速さとして伝わります
- **手ごたえ** — 柵にぶつかると柵の色の火花が散り、カメラが短く揺れます。強く着地したときも揺れます。
  揺れるのはカメラだけで、走りには一切影響しません

### 音

効果音はすべてその場で合成しています（音声ファイルは 1 つもありません）。
転がる音は速度と接地に追従し、着地・壁・スカイド・落下・カウントダウン・ゴールに音がつきます。
ブラウザの決まりで最初のタップまで音は鳴らせないので、それまでは静かに待ちます。
`せってい` の「音」で切り替えられます。

### かたちが転がりを決める

でっぱりのあるボールは、一定の半径では転がりません。1周のうち何度か出っぱりが下に来て地面を叩き、
ボールを跳ね上げ、速度を奪います。ここを物理として実装しているので、形を変えれば挙動が変わります。

**形はこのゲームで一番大きい選択です。** はじまりの丘（一番やさしいコース）を同じ運転で下ると：

| かたち | タイム |
| --- | --- |
| まる | 19.8 秒 |
| こつぶ | 23.5 秒 |
| しかく | 39.7 秒 |
| ランダム（でこぼこなもの） | 38〜45 秒 |

丸いボールの倍かかります。効いているのは 3 つで、どれも形から出ています
— 地面のつかみ方（でこぼこだと接地が安定しない）、転がり抵抗、そして出っぱりが地面を叩く跳ね。
「まる の 2 倍近くかかる」ことと「こつぶ は丸いので速いまま」の両方をテストで縛ってあります。

でこぼこすぎて本当に転がれない形もできますが、そのときは 10 秒のカウントで終わります（20個に1個ほど）。

かたちは **本体24種 × 組み立て3種 × 仕上げ5種** の組み合わせで作ります。

**組み立て**（そのまま／左右対称に折る／90度まわして重ねる）は、ボールがどれだけ均等かを決めます。
とくに「左右対称に折る」は重心のかたよりを消すので、**まっすぐ走るボールを狙って作れる**ようになります。
ランダム600個のうち、素直に走るボール（曲がり 0.15 未満）は 63個 → 80個 に増え、
重心のかたよりの中央値は 0.048 → 0.028 に下がりました。

**仕上げ**（そのまま／のばす・つぶす／殻にする／とげを生やす／まるくけずる）は、見た目と転がりの両方を変えます。
最後の2つは、本体だけでは作れなかった「とげとげ」「ちゃんと丸い」に届きます。

同じコースを自動運転で下ると、ランダム60個のタイムは **20秒〜61秒**（中央値37秒）に散ります。

### おもりの位置

**重心は自分で決められます。** 「ボールをつくる」の下にある丸いパッドが、後ろから見たボールです。
黄色い点をドラッグすると、そこにおもりが入ります。

まんなかなら、形が言うとおりの走りをします。外へ動かすほど、その形が持っていた素直さを手放します。

| おもりの位置 | まがり・うねり |
| --- | --- |
| まんなか | 0.00 |
| 半分ほど外 | 0.49 |
| いちばん外 | 0.99 |

パッドの全域が効くようにしてあります（半分の位置なら、ちょうど半分だけ荒れる）。
上に置いても横に置いても荒れ方は同じです — ボールは転がっているので、どの向きも
すぐに下になります。変わるのは**どちらへ振られるか**です。

**きれいな丸に、いちばん外までおもりを入れると、いちばん荒れたランダム形状と同じくらい暴れます。**
形をいじらずに難しさだけ足せる、という意味でもあります。

### 走りがなめらかでない

形が転がりに効く道はもう2つあります。どちらも**物理が区別する軸**で、遅さではなく走りの質を変えます。

**重心のずれ → うねる。** 重心が真ん中にないボールは、1回転するあいだに重い側が落ちて押し、
また持ち上げられて引き戻されます。1回転で差し引きゼロですが、その間じゅう感じられます。

**向きによる回りやすさの差 → 出たり止まったりする。** 重さが1本の線に沿って集まっているボール
（麺棒のような形）は、その線まわりには軽く回り、ほかの向きには重い。だから毎回転の一部で楽をして
残りで踏ん張ります。**1回転に2回**です — 線のまわりを回す仕事は、どちら端が上でも同じなので。

幅24m・まっすぐな坂を下ったときの、速度のムラ（0.5秒ごとの最大と最小の差 ÷ 平均速度）：

| かたち | 回りやすさの差 | はしりのムラ |
| --- | --- | --- |
| まる | 0.00 | 0.05 |
| こつぶ | 0.00 | 0.04 |
| しかく | 0.00 | 0.04 |
| ランダム（線状のもの） | 0.80 | **0.39** |

**まる の 7 倍**ムラがあります。左右対称に作られたボール（まる・こつぶ・しかく）は、
どの向きに回しても同じ仕事なので、差はちょうど 0 です。

どちらも**1回転で差し引きゼロ**にしてあります。遅さは既に抵抗が受け持っているので、
ここは「なめらかに走らない」だけを担当します。テストでも、ムラの大きいボールがちゃんと加速することを見ています。

### まっすぐ転がらない

遅くなるだけでなく、**でこぼこなボールは狙った線を保てません**。幅24m・まっすぐな坂を
ハンドルを切らずに90m下ったときの、横へのずれ：

| かたち | よこにずれた |
| --- | --- |
| まる | 0.00 m |
| こつぶ | 0.13 m |
| しかく | 1.39 m |
| ランダム | 0.9〜5.9 m |

理由は形から出ています。重心が真ん中にないボールは、転がるたびに重い側が回ってきて片方へ引っぱります。
その引っぱりは進むにつれて左右に振れるので、**当てられるのではなく、当て続けなければならない**ものになります。
`lopsided`（重心のかたより）と `bumpiness`（でこぼこ）の両方から出していて、
左右対称に作られたボール（まる・こつぶ・しかく）は かたより 0 ちょうどです。

**まる は 1 ミリも曲がりません。** きちんと作ったボールが勝手に曲がるなら、それは形ではなくゲームが
プレイヤーと戦っていることになるので、そこはテストで縛ってあります。同じボール・同じ坂なら
毎回まったく同じ曲がり方をします（覚えられない曲がりは、ただの雑音なので）。

でこぼこ度は「表面の凹凸の大きさ」と「本体からはみ出した面の割合」から出しています
（エディタに「でこぼこ」として表示）。実測した完走タイムは次のとおりです。

| ボール | でこぼこ | はじまりの丘 |
| --- | --- | --- |
| まる | 0% | 19.8秒 |
| でっぱり1個 | 23% | 23.8秒 |
| でっぱり2個 | 28% | 24.6秒 |
| でっぱり4個 | 37% | 26.3秒 |
| しかく | 48% | 36.1秒 |
| ランダム | 79% | 37.6秒 |

まん丸なボールのでこぼこ度はちょうど 0% で、この仕組みは一切かかりません。
標準のボールはグリッドいっぱいまで埋めず少し小さく（直径80cm）してあります。
そうしないと「ふやす」で足す場所がなくなるためです。

### 物理

ボールは点ではなく剛体として扱っています。回転そのものがシミュレーションの状態で、
地面はボールと接している一点だけで力を伝えます。すべっている分（接地点の速度）を
摩擦が削り取り、その削り取った分がそのままボールを回す力になります。

画面上のボールは、**物理が計算した回転をそのまま**描いています。補正はありません。

回転の向きは目で判断しにくい（ブロックのボールは4回対称なので高速域では逆に見えるうえ、
面の裏表が逆だと奥側が見えて反転する）ため、`src/render/ballSpin.ts` に一本化したうえで
`tests/ballSpin.test.ts` が四元数まで通して検証しています。符号を逆にすると6件中4件が落ちます。

ボールは 1 辺 18 マス（4,600 個以上）のブロックでできています。1 マスは 5cm 角なので、
ボール全体の大きさは変わらないまま、細かい形が作れます。
以前の 9 マス版で保存したボールは、読み込み時に 2×2×2 に展開して引き継がれます。

ボールには、進行方向がひと目でわかる**片寄った模様**をつけてあります。ブロックで作った球は
1/4回転するとまったく同じ形に戻るため、単色だと模様が1回転に4回めぐります。速度が出ると
その周期が画面の更新に追いつかなくなり、**映画で車輪が逆回転して見えるのと同じ理由で、
ボールが逆に回っているように見えます**（12m/s・30fpsで1周期あたり1.8フレーム）。
模様を片寄らせると目印が1回転に1回になり、どの速度・どのフレームレートでも正しく読めます。
模様は色だけの話なので、転がり方には一切影響しません。

ボールの半径は「見た目の接地半径」（**本体**の平らな外面までの距離）を使っています。
そのため描画されたボールはぴったり床に乗り、見た目どおりの速さで回ります。

ここで「本体」と書いたのが要点です。1マスだけ飛び出た突起で半径を決めてしまうと、
突起1個あるだけで半径が29%水増しされ、ボールは床から10cm浮いたまま、見た目より29%遅く回ります。
これはそのまま「滑っている／逆に回っている」ように見えます。
そこで、隣接3面以上でつながっているマスだけを本体とみなして半径を決めています。

コース上には何も置いていません。景色も光も、すべて床のふちより外側に配置しています
（最短でもふちから0.5m以上。テストで毎回確認しています）。

ここから、書き足さなくても次のことが起きます。

- 坂での加速は、すべる場合の `g·sinθ` ではなく、転がる場合の `g·sinθ /(1 + k)` になります
  （`k` は回しにくさ。中身の詰まった球なら 0.4 前後で、教科書どおり 5/7 に落ちます）
- ブロックの置き方で `k` が変わります。中心に寄せると出足が速く、外周に寄せると鈍くなります。
  エディタの「うごきだし」がこの値です
- 摩擦が足りない路面では、削り取りきれなかった分がそのまま「すべり」として残ります。
  氷では急な坂で直進していても滑り、ハンドルを切れば必ず滑ります。土けむりが出るのはそのときです
- 壁にぶつかると、跳ね返りと同時に壁をこするぶんの回転が加わります

**支えがあるのは、床が描かれている場所だけです。** コースの幅の外、床がとぎれた場所、
スタート線より手前、ゴールより先 — どこにも見えない床はありません。壁も描かれている高さ
（0.55m）までで、その上を飛び越えたボールは押し戻されません。
ハンドルの下方向はブレーキで、止まることはできても後ろには進みません。

床から 6m 下まで落ちるとスタート地点に戻されます。0.7 秒だけ静止してから再スタートしますが、
**その間もタイムは動き続けます**。落ちた回数は画面と結果に表示されます。

まったく進めなくなったとき（引っかかった、坂が尽きた、ブレーキを握りっぱなし）は
**10 秒のカウントダウン**が出て、0 でゲームオーバーになります。1m 進むたびにカウントは満タンに戻り、
落ちて戻されたときも仕切り直しになるので、走れているかぎり出ることはありません。

計算はすべて整数のままです。テストでは、実測した加速度を理論値と突き合わせています
（10度の坂で 0.961 対 理論 0.970、`回転速度 × 半径` と速度の一致は 0.1% 以内）。
描画側も実ブラウザで測っていて、1コース走りきったときの「回転から求めた距離 ÷ 実際に進んだ距離」は
1.000〜1.005、回転軸と進行方向の直交誤差は最大4%です。

### 設計のかんどころ

ゲームの進行は **1/120 秒の固定きざみ**で、**整数だけ**を使って計算します。
時計も、種のない乱数も、一切参照しません。
そのため、同じコース・同じボール・同じ操作を与えれば、どの端末でも一字一句同じ結果になります。

この性質から、次のことが素直に実現できています。

- **リプレイが正確**。1 ステップにつき小さな整数 1 つを保存するだけで、走りを完全に再現できます
- **遠くの景色を捨てられる**。見えていない場所の小物はひとまとめの「メモ」に置きかえ、近づいたら同じ内容で復元します。捨てても結果は変わりません
- **将来の複数人対戦の下地**。やりとりするのは操作だけで済み、巻き戻しと再計算の仕組み（`capture` / `rewind`）も用意してあります

今回はソロプレイのみですが、席は 4 人分用意してあります（`MAX_PLAYERS`）。

### テスト

364 件のテストがあります。数値計算、乱数の再現性、小物の一生、コースの形、転がりの物理、リプレイ、
巻き戻し、メッシュの生成、画面の組み立て、操作の読み取り、保存まわりを確認しています。

リプレイは「見る速さを変えても、フレームが乱れても、走りが 1 ビットも変わらない」ことと、
「終わったあとは 1 ステップも流れない」ことを確かめています（後者を落とすと、終端で止まっている間
ゴール音が毎フレーム鳴りつづけます）。柵は「描いてある高さと当たる高さが同じ」であることをテストで縛ってあるので、
片方だけ変えると落ちます。

物理のテストは、コードの出力をそのまま写したものではなく、坂の角度とボールの形から計算した
理論値と比べています。実装が現実の挙動からずれたら落ちます。

3 つのコースについては「素朴な自動運転で最後まで走りきれること」を毎回テストしています。
コース設計を変えて詰みが生まれた場合、テストが落ちて気づけます。

```bash
npm test
```

## 対応環境

WebGL が使える最近のブラウザで動きます（Chrome、Safari、Firefox、Edge）。
画面の狭い端末では表示を切り替え、ノッチやホームバーを避けて配置します。
`せってい` から、カメラの近さ・描画の細かさ・上下操作の反転を変更できます。
